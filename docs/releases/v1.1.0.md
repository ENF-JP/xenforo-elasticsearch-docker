## G1 — Design accepted

| | |
|---|---|
| **Cleared by / date** | ENF-JP, 2026-11-12 (same approval as G0) |
| **Design note** | The review findings and the version table in CHANGELOG.md. Two design decisions taken during build and reported back: (1) MariaDB default kept at 11.4 (LTS to 2029) and made selectable, rather than moved, because a newer major is a one-way change on an existing volume; (2) Dependabot limited to GitHub Actions and image pins covered by a monthly review issue instead, because Dependabot cannot read versions held in `.env` variables or `FROM ${ARG}` |
| **Threat model** | **AI-drafted.** Untrusted input reaching the stack: (a) the network — mitigated by loopback-only publishing, unpublished MariaDB/Elasticsearch, and now an engine-version check, since loopback isolation depends on Docker Engine ≥ 28.3.3 (CVE-2025-54388); (b) `stack/.env` values, written by the user or the setup script and passed to `docker compose exec` as argument arrays, never through a shell string; (c) third-party images and PECL packages pulled at build — mitigated by exact version pins and the monthly review; (d) pull-request content in CI — workflows use `pull_request` (not `pull_request_target`), a read-only token, `persist-credentials: false` and SHA-pinned actions. What breaks if an assumption fails: an unpinned or compromised image runs with access to the bind-mounted webroot; an engine below 28.3.3 exposes `127.0.0.1` ports to the LAN |
| **Personal data** | None, confirmed — the stack holds only a disposable local admin account the user creates; nothing is collected or transmitted by this repository. v1.1 additionally stops the installer opting the dev board into XenForo's anonymous usage statistics |
| **Schema change** | None in this repository. Upgrade/rollback for the *user's* data volumes (Elasticsearch and MariaDB version changes are one-way) is documented in [docs/upgrading.md](../upgrading.md) |
